# 1. Introduction（引言）

## 1.1 研究背景与动机

大型语言模型（LLMs）已经确立了测试时扩展（test-time scaling）的新范式，推动了模型性能的显著提升。然而，这种扩展范式受到** vanilla attention 机制二次计算复杂度**的根本约束，为超长上下文和推理过程带来了难以克服的瓶颈。

与此同时，长程场景和任务的出现——从复杂的 agentic 工作流到大规模跨文档分析——使得高效支持超长上下文对未来进步变得至关重要。虽然近期的开源努力已经推进了通用能力，但这种在处理超长序列时的核心架构低效性仍然是一个关键障碍，限制了测试时扩展的进一步收益，并阻碍了对长程场景和任务的深入探索。

## 1.2 核心贡献：DeepSeek-V4 系列

为了打破超长上下文中的效率壁垒，DeepSeek 开发了 **DeepSeek-V4 系列**，包括两个强大的混合专家（MoE）语言模型预览版：

| 模型 | 总参数量 | 激活参数量 | 支持上下文长度 |
|------|---------|-----------|---------------|
| **DeepSeek-V4-Pro** | 1.6T | 49B | 1M tokens |
| **DeepSeek-V4-Flash** | 284B | 13B | 1M tokens |

## 1.3 核心技术创新

### 1.3.1 架构创新

1. **流形约束超连接（mHC）**：加强传统残差连接
2. **混合注意力机制**：结合压缩稀疏注意力（CSA）和重型压缩注意力（HCA）
3. **Muon 优化器**：更快的收敛速度和更好的训练稳定性

### 1.3.2 基础设施创新

1. **单融合 kernel**：将 MoE 模块的计算、通信和内存访问完全重叠
2. **TileLang DSL**：平衡开发效率与运行时效率
3. **批不变和确定性 kernel 库**：确保训练和推理的位级可重现性
4. **FP4 量化感知训练**：用于 MoE expert 权重和 indexer QK 路径
5. **上下文并行两阶段管理**：管理压缩注意力
6. **异构 KV Cache 结构**：支持磁盘存储策略实现高效共享前缀复用

## 1.4 效率提升数据

在 **1M-token 上下文**场景下，相比 DeepSeek-V3.2：

| 模型 | 单 Token FLOPs | KV Cache 大小 |
|------|--------------|--------------|
| **DeepSeek-V4-Pro** | 27% | 10% |
| **DeepSeek-V4-Flash** | 10% | 7% |

## 1.5 预训练规模

- **DeepSeek-V4-Flash**: 在 **32T tokens** 上训练
- **DeepSeek-V4-Pro**: 在 **33T tokens** 上训练

## 1.6 后训练范式

采用**两阶段范式**：
1. **领域专家独立培养**：分别训练数学、编码、agent、指令遵循等领域的专家模型
2. **统一整合 via On-Policy Distillation (OPD)**：将不同专家能力通过蒸馏整合到统一模型中

# 2. Architecture（架构）

## 2.0 整体架构概述

DeepSeek-V4 系列**保留 Transformer 架构和 Multi-Token Prediction (MTP) 模块**，同时在 DeepSeek-V3 基础上引入三项关键升级：

1. **mHC（Manifold-Constrained Hyper-Connections）**：加强传统残差连接
2. **混合注意力架构**：通过 CSA 和 HCA 大幅提高长上下文效率
3. **Muon 优化器**：用于模型训练

对于 MoE 组件，仍采用 **DeepSeekMoE** 架构，只有微小调整。MTP 配置与 DeepSeek-V3 完全相同。

## 2.1 继承自 DeepSeek-V3 的设计

### 2.1.1 混合专家（Mixture-of-Experts）

- 采用 **DeepSeekMoE 范式**：设置细粒度路由专家和共享专家
- **激活函数变化**：从 `Sigmoid(·)` 改为 `Sqrt(Softplus(·))`
- **负载均衡策略**：
  - 辅助损失自由策略（auxiliary-loss-free）
  - 轻度序列平衡损失（sequence-wise balance loss）防止单序列内极端不平衡
- **路由目标节点数量约束**：已移除
- **并行策略**：重新设计以保持训练效率
- **前几层变化**：将初始 Transformer 块的密集 FFN 层替换为使用 **Hash 路由**的 MoE 层

### 2.1.2 多 Token 预测（Multi-Token Prediction）

- 设置 MTP 模块和目标
- 配置与 DeepSeek-V3 完全相同

## 2.2 流形约束超连接（Manifold-Constrained Hyper-Connections, mHC）

### 2.2.1 标准超连接（Standard HC）

标准 HC 将残差流的宽度扩展 **n_hc 倍**：
- 形状从 `R^d` 扩展到 `R^(n_hc×d)`
- 引入三个线性映射：输入映射 A^l、残差变换 B^l、输出映射 C^l
- 更新公式：`X^(l+1) = B^l X^l + C^l F^l(A^l X^l)`

### 2.2.2 流形约束残差映射（Core Innovation）

**核心创新**：将残差映射矩阵 B^l 约束到**双随机矩阵流形**（Birkhoff 多面体）上：

```
B^l ∈ M := {M ∈ R^(n×n) | M 1_n = 1_n, 1_n^T M = 1_n^T, M ≥ 0}
```

**约束效果**：
- 确保映射矩阵的谱范数 ≤ 1，残差变换是非扩张的
- 增加前向和反向传播的数值稳定性
- 集合 M 在乘法下闭合，保证深层 mHC 堆叠的稳定性
- 输入/输出变换 A^l 和 C^l 通过 Sigmoid 函数约束为非负且有界

### 2.2.3 动态参数化（Dynamic Parameterization）

三个线性映射的参数是**动态生成**的，分解为动态（输入相关）和静态（输入独立）分量：

```
˜A^l = α_pre^l · (ˆX^l W_pre^l) + S_pre^l
˜B^l = α_res^l · Mat(ˆX^l W_res^l) + S_res^l  
˜C^l = α_post^l · (ˆX^l W_post^l)^T + S_post^l
```

### 2.2.4 参数约束应用

- **输入/输出映射**：通过 Sigmoid 函数确保非负有界
- **残差映射**：通过 **Sinkhorn-Knopp 算法**投影到双随机矩阵流形
  - 首先对 ˜B^l 应用指数函数确保正性
  - 然后迭代执行列和行归一化
  - 选择 t_max = 20 作为实际值

## 2.3 混合注意力：CSA 和 HCA

### 2.3.1 压缩稀疏注意力（Compressed Sparse Attention, CSA）

**核心思想**：
1. 将每 **m 个 token** 的 KV Cache 压缩为 **1 个条目**
2. 然后应用 **DeepSeek Sparse Attention (DSA)**：每个查询 token 只关注 **k 个**压缩 KV 条目

#### 2.3.1.1 压缩 Key-Value 条目

给定输入隐藏状态 `H ∈ R^(n×d)`：
- 计算两个系列 KV 条目：`C_a, C_b ∈ R^(n×c)` 和对应压缩权重 `Z_a, Z_b ∈ R^(n×c)`
- 每 m 个 KV 条目根据压缩权重和可学习位置偏置压缩为 1 个条目
- 采用**重叠压缩策略**：C_b 用于 C_comp^i 和 C_comp^(i+1) 的索引重叠

#### 2.3.1.2 Lightning Indexer 稀疏选择

1. 对 C_comp 执行与获取 C_comp 相同的压缩操作，获取压缩 indexer keys `K_I^Comp`
2. 为查询 token t 低秩生成 indexer queries `{q_I^t,1; q_I^t,2; ...; q_I^t,n_I^h}`
3. 计算 index score：使用 ReLU 激活函数
4. 使用 **top-k 选择器**选择要保留的压缩 KV 条目子集

#### 2.3.1.3 共享 Key-Value MQA

- 每个压缩 KV 条目同时作为 attention key 和 value
- 从压缩潜在向量生成注意力查询
- 执行 MQA：`o_t,i = CoreAttn(query=q_t,i, key=CSprsComp_t, value=CSprsComp_t)`

#### 2.3.1.4 分组输出投影（Grouped Output Projection）

- 将 n_h 个输出分成 g 组
- 每组输出投影到 d_g 维中间输出（其中 d_g < c·n_h / g）
- 最后将所有中间输出投影到最终 d 维注意力输出

### 2.3.2 重型压缩注意力（Heavily Compressed Attention, HCA）

**核心思想**：更激进的压缩——每 **m' (≫ m)** 个 token 的 KV Cache 合并为 **1 个条目**，不执行稀疏注意力。

#### 2.3.2.1 压缩 Key-Value 条目

- 与 CSA 类似，但使用更大的压缩率 m'（≫ m）
- **不执行重叠压缩**
- 压缩公式：
  ```
  S = Softmax_row(Z + B)
  C_comp^i = Σ(j=m'i to m'(i+1)-1) S_j ⊙ C_j
  ```

#### 2.3.2.2 共享 KV MQA 和分组输出投影

- 与 CSA 相同的策略
- 每个查询 token 关注所有压缩 KV 条目（无稀疏性）

### 2.3.3 其他细节

#### 2.3.3.1 查询和 Key-Value 条目归一化

- 在核心注意力操作之前，对查询的每个头和压缩 KV 条目的唯一头执行额外的 **RMSNorm** 操作
- 避免注意力 logits 爆炸，提高训练稳定性

#### 2.3.3.2 部分旋转位置嵌入（Partial RoPE）

- 对 CSA 和 HCA 的注意力查询、KV 条目和核心注意力输出**部分应用 RoPE**
- 对每个查询向量和 KV 条目向量的**最后 64 维**应用 RoPE
- 对核心注意力输出的最后 64 维应用位置 **-i** 的 RoPE，使输出携带**相对位置嵌入**

#### 2.3.3.3 滑动窗口注意力额外分支

- 为严格保持因果性，每个查询只关注前面的压缩 KV 块
- 引入**补充注意力分支**以更好地建模局部依赖
- 每个查询 token 额外生成对应最近 **n_win 个 token** 的 n_win 个未压缩 KV 条目
- 在 CSA 和 HCA 的核心注意力中，这些滑动窗口 KV 条目与压缩 KV 条目一起使用

#### 2.3.3.4 注意力 Sink

- 设置一组可学习的 sink logits `{z'_1, z'_2, ..., z'_n_h}`
- 对于第 h 个注意力头，将 `Exp(z'_h)` 加到注意力分数的分母
- 允许每个查询头调整其总注意力分数，使其不等于 1，甚至接近 0

### 2.3.4 效率讨论

**效率提升来源**：
1. **混合存储格式**：BF16 用于 RoPE 维度，FP8 用于其余维度，KV Cache 大小减少近一半
2. **FP4 精度**：Lightning indexer 中的注意力计算使用 FP4
3. **更小的 top-k**：相比 DeepSeek-V3.2，选择更小的注意力 top-k
4. **压缩注意力**：大幅减少 KV Cache 大小和计算 FLOPs

**效率数据**：
- 以 BF16 GQA8（头维度 128）为基准，DeepSeek-V4 系列的 KV Cache 大小可减少到约 **2%**
- 在 1M 上下文设置下，即使更大的 DeepSeek-V4-Pro 也只需 **27% 单 Token FLOPs** 和 **10% KV Cache 大小**

## 2.4 Muon 优化器

### 2.4.1 基本配置

- **AdamW**：用于 embedding 模块、预测头模块、mHC 模块的静态偏置和门控因子、所有 RMSNorm 模块的权重
- **Muon**：用于所有其他模块

### 2.4.2 Muon 算法核心

```
对于每个训练步骤：
  对于每个逻辑独立的权重 W：
    G_t = ∇_W L_t(W_{t-1})  # 计算梯度
    M_t = μ M_{t-1} + G_t   # 累积动量
    O'_t = HybridNewtonSchulz(μ M_t + G_t)  # Nesterov + 混合 Newton-Schulz
    O_t = O'_t · √(max(n,m)) · γ  # 重新缩放更新 RMS
    W_t = W_{t-1} · (1 - ηλ) - η O_t  # 执行权重衰减和更新
```

### 2.4.3 混合 Newton-Schulz 迭代

对于给定矩阵 M，Newton-Schulz 迭代旨在将 M 近似正交化为 **U·V^T**。

**两阶段混合策略**：
1. **前 8 步**：使用系数 `(a, b, c) = (3.4445, -4.7750, 2.0315)` 驱动快速收敛
2. **最后 2 步**：切换到系数 `(a, b, c) = (2, -1.5, 0.5)` 稳定地将奇异值精确置为 1

### 2.4.4 避免注意力 Logits 爆炸

- DeepSeek-V4 系列的注意力架构允许直接对注意力查询和 KV 条目应用 RMSNorm
- 有效防止注意力 logits 爆炸
- 因此**不使用 QK-Clip 技术**

# 3. General Infrastructures（通用基础设施）

## 3.1 专家并行中的细粒度通信-计算重叠

### 3.1.1 通信延迟可隐藏

**关键洞察**：在 MoE 层中，通信延迟可以有效地隐藏在计算之下。

DeepSeek-V4 系列中，每个 MoE 层可分解为四个主要阶段：
- 两个**通信绑定**阶段：Dispatch 和 Combine
- 两个**计算绑定**阶段：Linear-1 和 Linear-2

**分析发现**：单个 MoE 层内，通信总时间小于计算时间。因此，将通信和计算融合成统一流水线后，计算仍是主导瓶颈。

### 3.1.2 细粒度 EP 方案

**方案核心**：将专家分割并调度成**波次（waves）**。

- 每波由一小部分专家组成
- 当波内所有专家完成通信后，计算可立即开始
- **稳态下**：当前波计算、下一波的 token 传输、已完成专家的结果发送三者**并行**

### 3.1.3 性能与开源

- 在 NVIDIA GPU 和 HUAWEI Ascend NPU 平台上验证
- 相比强非融合基线：通用推理工作负载实现 **1.50~1.73×** 加速
- 延迟敏感场景（RL rollout、高速 agent 服务）高达 **1.96×**
- 开源 CUDA mega-kernel 实现：**MegaMoE**

### 3.1.4 观察与建议

1. **计算-通信比率**：
   - 完全重叠取决于计算-通信比，而非仅带宽
   - 公式：`C/B ≤ V_comp/V_comm`
   - DeepSeek-V4-Pro 每 token-expert 对需要 6hd FLOPs 但仅需 3h bytes 通信
   - 简化为：`C/B ≤ 2d = 6144 FLOPs/Byte`

2. **功率预算**：极端 kernel 融合使计算、内存、网络同时高负载，功率节流成为关键限制因素

3. **通信原语**：采用**拉取（pull-based）方法**，避免细粒度推送的高通知延迟

4. **激活函数建议**：用低成本逐元素激活替换 SwiGLU

## 3.2 TileLang：灵活高效的 Kernel 开发

### 3.2.1 核心价值

- 平衡**开发效率**与**运行时效率**
- 快速原型设计同时支持深度迭代优化
- 与 TileLang 社区紧密合作

### 3.2.2 Host Codegen 减少调用开销

**问题**：加速器性能增长，CPU 端编排开销日益突出。

**解决方案**：
- 在 IR 层面共同生成设备 kernel 和轻量级 host launcher
- 嵌入数据类型、rank/shape 约束、stride/layout 假设等元数据
- launcher 降低到 TVM-FFI 框架上的 host 源码
- CPU 端验证开销从**数十到数百微秒**降至**小于 1 微秒**

### 3.2.3 SMT 求解器辅助形式整数分析

**挑战**：TileLang kernel 涉及复杂张量索引运算，需要强大的形式整数分析能力。

**解决方案**：
- 集成 **Z3 SMT 求解器**到 TileLang 的代数系统
- 翻译 TileLang 整数表达式到 Z3 的 QF_NIA（非线性整数算术）
- ILP 求解器无缝解决 kernel 中的标准线性整数表达式
- 固有非线性推理能力有效处理向量化和可变张量形状等高级挑战
- 在合理资源限制下，Z3 提升整体优化性能，编译时间开销仅几秒

### 3.2.4 数值精度与位级可重现性

- **默认优先精度**：禁用快速数学优化
- 提供精确的 IEEE-754 语义内在函数（如 `T.ieee_fsqrt`）
- **位级可重现性**：对齐 TileLang 的代数简化和降低规则与主流 CUDA 工具链
- 布局注解允许用户固定降低决策，确保位相同输出
- 保守默认下 TileLang kernel 保持竞争力

## 3.3 高性能批不变和确定性 Kernel 库

### 3.3.1 批不变性（Batch Invariance）

**定义**：任何给定 token 的输出与批次内的位置无关，位级相同。

**主要挑战与解决方案**：

#### Attention
- **问题**：不能使用 split-KV 方法（将单个序列的注意力计算分布到多个 SM）
- **解决方案**：开发**双 kernel 策略**
  - **Kernel 1**：单个 SM 内计算整个序列的注意力输出
  - **Kernel 2**：多个 SM 处理单个序列，最小化最终部分填充 wave 的延迟
  - 两个 kernel 的计算路径精心设计，确保位相同
  - 使用分布式共享内存在 thread-block clusters 内实现高速数据交换

#### 矩阵乘法
- **问题**：传统 cuBLAS 不能实现批不变性
- **解决方案**：端到端替换为 **DeepGEMM**
- **小批量优化**：引入一组优化，使矩阵乘法在大多数主要场景下匹配或超越标准 split-k 性能

### 3.3.2 确定性（Determinism）

**非确定性根源**：通常来自非确定性累积顺序，通常由于原子加法指令使用。

#### Attention 反向传播
- **问题**：稀疏注意力的反向传播使用 `atomicAdd` 累积 KV token 梯度
- **解决方案**：为每个 SM 分配单独的累积缓冲区，然后跨所有缓冲区执行全局确定性求和

#### MoE 反向传播
- **问题**：多个 SM 从不同 rank 并发写入同一缓冲区
- **解决方案**：每个 rank 内 token 顺序预处理器 + 跨 rank 缓冲区隔离

#### mHC 中的矩阵乘法
- **问题**：输出维度仅为 24，小批量必须使用 split-k
- **解决方案**：分别输出每个 split 部分，在后续 kernel 中执行确定性归约

## 3.4 FP4 量化感知训练

### 3.4.1 应用范围

应用于两个组件：
1. **MoE expert 权重**：GPU 内存占用的主要来源
2. **CSA indexer 中 QK 路径**：QK 激活以 FP4 完全缓存、加载和相乘

### 3.4.2 额外优化

- **Index scores 量化**：从 FP32 量化到 BF16
- **效果**：top-k 选择器实现 **2× 加速**，KV 条目召回率保持 **99.7%**

### 3.4.3 FP4 到 FP8 无损去量化

- FP8 (E4M3) 相比 FP4 (E2M1) 有 **2 个额外指数位**，提供更大动态范围
- 只要 FP8 量化块（128×128 tiles）内 FP4 子块（1×32 tiles）的最大和最小 scale 因子比率不超过阈值
- 细粒度 scale 信息可完全被 FP8 扩展动态范围吸收
- 整个 QAT pipeline 完全复用现有 FP8 训练框架，无需修改

### 3.4.4 推理和 Rollout

- 不涉及反向传播，直接使用真实 FP4 量化权重
- 确保采样期间模型行为与在线部署完全一致
- 减少 kernel 内存加载实现实际加速，显著降低内存消耗

## 3.5 训练框架

### 3.5.1 Muon 高效实现

**挑战**：Muon 需要完整梯度矩阵计算参数更新，与 ZeRO 冲突。

**混合 ZeRO 分桶策略**：

#### 密集参数
- 限制 ZeRO 并行最大大小
- 使用**背包算法**分配参数矩阵到各 rank
- 每个 rank 的 bucket 填充到最大 bucket 大小（padding 通常小于 10%）
- 当 DP 总大小超过 ZeRO 限制时，在额外 DP 组冗余计算 Muon 更新

#### MoE 参数
- 每个 expert 独立优化
- 展平所有 expert 的 down projection、up projection 和 gate 矩阵
- 均匀分配展平向量，不分割任何逻辑独立矩阵
- 专家数量大，ZeRO 并行限制不施加，padding 开销可忽略

#### 额外优化
- 连续相同形状参数自动合并，实现 Newton-Schulz 迭代的批量执行
- MoE 梯度随机量化到 BF16 精度跨 DP rank 同步，减半通信量
- 两阶段方法替代树或环 reduce-scatter collectives

### 3.5.2 mHC 成本效益实现

**挑战**：mHC 相比传统残差连接增加激活内存消耗和流水线阶段间通信量。

**优化策略**：
1. 为训练和推理精心设计和实现 mHC 融合 kernel
2. **选择性检查点重新计算策略**：
   - 重新计算层间大多数隐藏状态和所有归一化层输入
   - 避免重新计算计算密集型操作
3. 调整 DualPipe 1F1B 重叠方案以适应增加的流水线通信

**效果**：mHC 墙钟时间开销仅为重叠 1F1B 流水线阶段的 **6.7%**

### 3.5.3 长上下文注意力的上下文并行

**挑战**：
1. 训练样本从多个序列打包，每个序列独立压缩因子 m（或 m'），压缩 KV 长度通常小于 s/m 且各 rank 不同
2. 压缩需要 m 个连续 KV 条目，可能跨越两个相邻 CP rank 边界

**两阶段通信方案**：
1. **阶段 1**：每个 rank i 发送最后 m 个未压缩 KV 条目到 rank i+1
2. **阶段 2**：跨所有 CP rank 执行 all-gather，收集本地压缩 KV 条目

### 3.5.4 扩展自动微分用于灵活激活检查点

**问题**：传统激活检查点实现在整个模块粒度上运行，无法在重计算成本和激活内存占用之间实现最优权衡。

**解决方案**：实现**张量级激活检查点机制**，具有自动微分支持。

**工作流程**：
1. 开发者仅实现前向传递，选择性标记各个张量进行自动检查点和重新计算
2. 框架使用 TorchFX 追踪完整计算图
3. 对每个标记张量执行反向遍历，识别其重新计算所需的最小子图
4. 在反向逻辑中正好在相应梯度计算之前插入这些最小子图

**优势**：
- 相比手动实现无额外开销
- 重新计算通过直接释放 GPU 内存并复用重新计算张量的存储指针实现，无任何 GPU 内存复制
- 自动去重共享存储的张量（如 reshape 操作的输入和输出）

## 3.6 推理框架

### 3.6.1 KV Cache 结构与管理

#### DeepSeek-V4 中的异构 KV 条目

混合注意力机制引入多种 KV 条目类型：
- **Lightning indexer**：引入额外的 KV Cache 维度，嵌入大小与主注意力不同
- **CSA/HCA 压缩**：序列长度分别压缩 1/m 和 1/m'，减少总 KV Cache 大小
- **滑动窗口注意力 (SWA)**：具有不同的 KV Cache 大小，以及单独的缓存命中和驱逐策略

#### 状态缓存用于 SWA 和未压缩尾 Token

**解决方案**：采用替代缓存管理机制，将 SWA 和压缩分支的未压缩尾 token 视为状态空间模型。

- 预分配固定和有限大小的状态缓存池
- 动态分配给每个序列

#### 稀疏注意力 Kernel 协同设计

**挑战**：高性能注意力 kernel 通常假设每个块固定数量的 token（对应 CSA 中 B·m 个、HCA 中 B·m' 个原始 token）。

**解决方案**：共同设计 KV Cache 布局和稀疏注意力 kernel。
- 不同层可容纳可变 token 每块而不影响性能
- 每个块的原始 token 数可以是 **lcm(m, m')** 的任意倍数

### 3.6.2 磁盘 KV Cache 存储

**目的**：消除共享前缀请求的重复预填充。

#### CSA/HCA 的压缩 KV 条目

- 简单地将所有压缩 KV 条目存储到磁盘
- 当请求命中存储前缀时，读取并复用对应前缀的压缩 KV 条目
- 对于尾部不完整块中的前缀 token，仍需重新计算

#### SWA KV 条目

**三种策略**：

1. **完整 SWA 缓存**：
   - 存储所有 token 的完整 SWA KV 条目
   - 计算零冗余，但 SSD 存储访问不平衡（写入密集）

2. **定期检查点**：
   - 每 p 个 token 检查点 SWA KV 条目的最后 n_win 个 token
   - 通过调优 p 在存储和计算之间实现按需权衡

3. **零 SWA 缓存**：
   - 不存储任何 SWA KV 条目
   - 利用缓存的 CSA/HCA KV 条目，重新计算最后 n_win·L 个 token 以恢复 L 层模型的最后 n_win 个 SWA KV 条目

### 4.2.3 缓解训练不稳定性

#### 问题分析

训练万亿参数 MoE 模型面临显著稳定性挑战。尖峰发生与 MoE 层中的异常值密切相关，路由机制本身似乎加剧了这些异常值的出现。

#### 解决方案

##### 1. 预期路由（Anticipatory Routing）

**发现**：解耦主干网络和路由网络的同步更新显著提高训练稳定性。

**方法**：
- 在步骤 t，使用当前网络参数 θ_t 进行特征计算
- 路由索引使用历史网络参数 θ_{t-Δt} 计算和应用
- 在步骤 t-Δ_t 预先获取步骤 t 的数据
- "预期"计算并缓存路由索引供后续使用

**基础设施优化**：
1. 仅需单次前向传递预计算路由索引
2. 精心安排流水线执行和 EP 通信重叠
3. 预期路由的额外墙钟时间开销成功限制在约 **20%**
4. 自动检测机制：仅在发生损失尖峰时触发短期回滚并激活预期路由

##### 2. SwiGLU  clamping

**方法**：在 SwiGLU 的线性分量上应用 clamping 到 [-10, 10]，门分量上界限制为 10。

**效果**：
- 有效消除异常值
- 大幅帮助稳定训练过程
- 不影响性能

# 5. Post-Training（后训练）

## 5.1 后训练流水线

### 5.1.1 领域专家训练

#### 两阶段范式

1. **Supervised Fine-Tuning (SFT)**：在高质量领域特定数据上建立基础能力
2. **Reinforcement Learning (RL)**：使用 GRPO 优化领域对齐行为

#### 推理模式

DeepSeek-V4 系列支持三种推理模式：

| 模式 | 特性 | 典型用例 |
|------|------|---------|
| **Non-think** | 快速、基于习惯或简单规则的直觉响应 | 日常任务、紧急反应、低风险决策 |
| **Think High** | 意识逻辑分析，较慢但更准确 | 复杂问题解决、规划、中等风险决策 |
| **Think Max** | 将推理推到极致，较慢但最强大 | 探索模型推理能力边界 |

**Think Max 指令**：注入特定系统提示引导模型推理过程，包括绝对最大推理努力、彻底分解问题到根本原因、显式写出完整思考过程等。

#### 生成奖励模型（Generative Reward Model）

**传统方法问题**：难验证任务传统上依赖 RLHF，需要大量人类标注训练标量奖励模型。

**创新方法**：
- 放弃传统基于标量的奖励模型
- 使用**生成奖励模型 (GRM)** 评估策略轨迹
- **直接对 GRM 本身应用 RL 优化**
- 演员网络本身充当 GRM，评判能力和生成能力联合优化
- 模型内部推理能力固有融合到评估过程中
- 仅需最少多样化人类标注即可实现卓越性能

#### 工具调用 schema 和特殊 Token

- 使用专门的 `<think>　　</think>` 标签界定推理路径
- 引入新工具调用 schema：使用特殊 `|DSML|` token 和基于 XML 的格式
- XML 格式有效缓解转义失败并减少工具调用错误

#### 交错思考（Interleaved Thinking）

**问题**：DeepSeek-V3.2 中每个新用户turn会刷新所有累积推理内容。

**改进策略**：
1. **工具调用场景**：整个对话中保留完整推理内容，维护跨所有轮次的连贯累积思维链
2. **一般对话场景**：保持原始策略——新用户消息到达时丢弃先前turn的推理内容

#### Quick Instruction

**问题**：辅助任务（判断是否触发网络搜索、意图识别等）需要单独小模型，存在冗余预填充。

**解决方案**：
- 直接在输入序列附加专用特殊 token
- 每个 token 对应特定辅助任务
- 直接复用已计算的 KV Cache
- 完全避免冗余预填充
- 显著减少用户感知的时间到第一个 token (TTFT)

### 5.1.2 On-Policy Distillation (OPD)

#### 核心思想

使用多教师 **On-Policy Distillation** 作为将专家能力合并到最终模型的主要技术。

**形式化定义**：给定 N 个专家模型 `{π_E1, π_E2, ..., π_EN}`，OPD 目标函数为：

```
L_OPD(θ) = Σ(i=1 to N) w_i · D_KL(π_θ ∥ π_E_i)
```

#### OPD 流程

1. 从学生 π_θ 采样训练轨迹
2. 计算反向 KL 损失 D_KL(π_θ ∥ π_E_i)
3. 统一策略 π_θ 选择性地学习与当前任务上下文相关的专家知识
4. 超过 **10 个教师模型**覆盖各个领域蒸馏到单一学生模型

#### 全词汇表 Logit 蒸馏

**传统方法问题**：简化为 token 级 KL 估计导致高方差梯度估计和训练不稳定。

**解决方案**：
- 在 OPD 中采用**全词汇表 logit 蒸馏**
- 保留完整 logit 分布计算反向 KL 损失
- 更稳定的梯度估计
- 确保教师知识忠实蒸馏

## 5.2 RL 和 OPD 基础设施

### 5.2.1 FP4 量化集成

- **Rollout 和所有推理前向传递**应用 FP4 量化加速
- 训练步骤通过无损 FP4 到 FP8 去量化模拟
- 直接使用原生 FP4 权重进行 rollout 和推理

### 5.2.2 全词汇表 OPD 高效教师调度

**挑战**：简单实现全词汇表 KL 损失在词汇量 |V| > 100k 时即使倾倒到磁盘也是禁止的。

**解决方案**：
1. 教师权重卸载到集中式分布式存储，按需加载，ZeRO 类参数分片减轻 I/O 和 DRAM 压力
2. **缓存最后层教师隐藏状态**在集中缓冲区
3. 训练时检索缓存状态并通过相应预测头模块重构完整 logit
4. 按教师索引对训练样本排序，最小化 GPU 内存占用
5. 所有参数和隐藏状态加载/卸载操作异步后台执行
6. 专用 TileLang kernel 计算精确 KL 散度

### 5.2.3 可抢占容错 Rollout 服务

**问题**：GPU 集群中任何运行任务可能随时被抢占，硬件故障普遍。

**解决方案**：
- 为每个生成请求实现**token 级预写日志 (WAL)**
- 生成新 token 时立即追加到请求 WAL
- 抢占时暂停推理引擎，保存未完成请求的 KV Cache
- 恢复时使用持久化 WAL 和保存的 KV Cache 继续解码
- 即使发生致命硬件错误，也可使用 WAL 中持久化 token 重新运行预填充重构 KV Cache

**正确性保证**：从零重新生成是不数学正确的——较短响应更可能在中断中存活，从零重新生成会使模型更容易产生较短序列。

### 5.2.4 百万 Token 上下文 RL 框架扩展

**优化**：
1. **分解 rollout 数据格式**：轻量级元数据和重型每 token 字段
2. **元数据全局加载**：执行全局 shuffle 和打包布局计算
3. **重型每 token 字段**：通过共享内存数据加载器消除节点内数据冗余
4. **动态 mini-batch 数量**：基于工作负载，允许计算吞吐量和 I/O 重叠之间的有效权衡

### 5.2.5 Agentic AI 沙箱基础设施

**DSec (DeepSeek Elastic Compute)**：
- 生产级沙箱平台
- 三个 Rust 组件：API 网关 (Apiserver)、per-host agent (Edge)、集群监控器 (Watcher)
- 通过自定义 RPC 协议互连
- 基于 3FS 分布式文件系统水平扩展
- 单个 DSec 集群管理**数十万并发沙箱实例**

#### DSec 四大核心设计

1. **四个执行基底，一个统一接口**：
   - **Function Call**：无状态调用到预热容器池
   - **Container**：完全 Docker 兼容，EROFS 按需加载
   - **microVM**：基于 Firecracker，VM 级隔离
   - **fullVM**：基于 QEMU，支持任意客户操作系统

2. **通过分层存储实现快速镜像加载**：
   - 容器：基础镜像和文件系统提交存储为 3FS 支持的只读 EROFS 层
   - microVM：overlaybd 磁盘格式，只读基础层在 3FS 上

3. **大规模并发下的密度优化**：
   - 缓解虚拟化环境中的重复页面缓存
   - 应用内存回收实现安全过量使用
   - 减少容器运行时自旋锁争用

4. **轨迹日志和抢占安全恢复**：
   - 持久化记录每个命令调用及其结果
   - 目的：客户端快速前进、细粒度溯源、确定性回放
