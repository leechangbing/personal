如何设计业务指标
业务与指标的关系
1. 指标的核心目的：验证业务的运营逻辑是否有效，反应业务的运营状况；
2. 数据/指标看板的两套逻辑：
  1. 一套是大盘指标，反映整个业务健康运转的状况；
  2. 另一套是针对特定的下钻维度，业务自己的运营逻辑是否生效；

好的指标具备的特征
1. 【明确呈现业务逻辑，突出重点数据】好的指标呈现的逻辑必须契合业务的运营逻辑和转化链路，有多个指标时，要基于判断力选择最重要的指标、不用复合型指标，既有过程指标又有结果指标；
2. 【与业务表现有直接关联】好的指标跟具体的业务动作、用户场景、用户行为、商业价值有直接关系，避免人工定义、二次加工过。避免无关的指标、罗列或者汇总数据。
3. 【能支撑业务判断】数据口径清晰易懂，需思考统计这个数据是为了支撑什么业务判断，充分考虑业务场景来设计数据指标；好的指标描述数据，而不是传递概念。
4. 【一手数据/指标】一手数据是根据访谈、问卷、测定等事实层面，收集或者运算推导出来的数据。

指标解读方法
1. 【全局视角】培养全局视角，迭代决策链路，学会发现问题和做假设；
2. 【观察指标简联系】观察一个数据有可能导致的影响，以及可能导致其他数据的变化，能快速定位问题；
3. 【剥离数据】分析数据会影响/不会影响什么，快速把不会影响的事情剥离开；
4. 【先看规模，再看质量】先看数据的规模，即影响用户的占比/覆盖率，在看质量/效率；
5. 【定结果指标】定业务目标时，要有清晰可衡量的结果指标，不纠结过程指标；
6. 【定量描述指标】指标变化的正确描述定量，要描述具体的数据变化，应用「A->B(+xx%)」
7. 【对结果监控】推荐因素发生变化的时候，什么指标体系会被影响，需要的是结果的监控；

指标解读误区
1. 慎用外部归因，不要强行和业务相关性归因；当实在无法归因的时候，也不要强行归因；可以写这段时间做了啥，可能有相关性；
2. 不要用一堆数解释另一个数：归因要有业务sense，不要用A数解释B数，而是应该用业务逻辑解析变化；
3. 不看复合型数据：明确业务的核心指标是设什么，做好数据隔离；只看相关数据，不看多个口径的数据；
4. 不要定性描述：指标变化不要定性描述，显著、大幅、极大、全面...这类主观且不明确的表述方法不要用；

阵地战打累了怎么办？
1. 有哪些事情，在核心指标层面可能带来10%的收益，长期收益的事情，那些是50%，那些能重塑出来一个行业，长出一个新东西。
2. 有哪些事情，一直觉得重要，也一直在做，但是一直没有结果，投入度是不是不够，和行业差距有多少，是不是有多少人做多少事。
3. 有哪些事情，很多人在做，但是彼此依赖又彼此隔阂，各自都做不好，做的不舒服，事情的owner和团队配合，是不是不明确？
4. 有哪些事情，做的人其实不是充分认同和认可，但是被要求一定要做的；有哪些事情，其实不重要或者收益可能不大于1%，但是浪费了大量人力和精力。
5. 如何「解放」和「强化」运营驱动力，如何通过运营释放行业生产力，战术和打法层面，是不是重视、讨论和支持不够，我们有没有大炮和火箭，我们的运营会不会用。
6. 团队越来越大，人越来越多，高阶人选也越来越多，但是好像真正能打仗，有独当一面能力、经历的人反而没有变多，或者对于能够独当一面的要求变得越来越高。
7. 某一个新方向，或者新业务，想要做好，需要联动和协调的团队也越来越多。团队内新人被赋予重任，快速成长和被看见的机会是不是越来越少。
8. 擅长某方便的人，会不会一直在陷入于擅长的领域，疲于奔命但没办法在新的领域得到突破和提升，也没有精力去支持好其他业务的需求。
9. 我们最初是怎么成长起来的，我们成长最快的时候是什么样子，现在还有没有当时成长起来，所必须得条件？
