写文档前，最重要的是充分理解写文档的背景信息和目标，动笔前务必确认是否想清楚我为什么要写，在什么情况下，以什么视角来写这个文档。

接受信息和实际诉求的偏差

自上而下传递的很多都是「碎片化信息」，没搞清楚对方想要啥，认为对方一直在变，导致自己被扯着跑，没有产出。

case1 用户画像分析要看什么
某次IES双周会提及一个新功能，形成一个ToDo：分析下这个新功能的用户画像。同学接到需求后，迅速产出文档，对用户&主播画像进行了详尽的分析，基于画像分析产出若干结论。只罗列信息，没有符合预期的产出。

为什么要做这件事，是否清楚预期？
背景是IES各方参会者对新业务不了解，预期对这部分业务能有清晰的定位和定性的认知，不是真的想知道用户年龄地域分布，更想知道业务对此的思考是否深入。

应该产出的是什么？
除了用户画像外，对业务的理解、分析、规划，更深的思考，且能够通过简单的表达，让各方认同这个规划；
接受的是用户画像的需求信息，但背后的原因并不只是想要用户画像。预期不一致，就会走偏。

case3 用户的嘴，骗人的鬼
100年前，福特公司创始人亨利.福特调研客诉：“您需要一个什么样的更好的交通工具？”几乎所有人所有人的回答都是：“我需要一匹更快的马”。很多人听到这个答案，立马到马场选马配种，以满足客户需求。但福特却没有往马场跑，而是接着往下问。
福特：“你为什么需要一匹更快的马？”
客户：“因为可以跑得更快！”
福特：“你为什么需要跑的更快？”
客户：“因为这样，可以更快地到达目的地。”
福特：“所以，你要一匹更快的马的真正用意是？”
客户：“用更短的时间、用更快的时间到达目的地！”
用户会用同样的方式沟通，用户说想要xx需求，真把这个需求做了，ta不一定会用。要思考的是背后的问题是什么，要解决ta的问题，而不是听了ta的需求直接做。

搞清楚预期，才能达到/超出预期
没搞清楚预期就执行，一开始就是错的，不可能达到预期。那么，如何搞清楚预期呢？
- 【多想】多想两次为什么和怎么做
- 【多问】信息量不够，过程不清楚 => 去问
- 【验证】当有了想法，可形成框架性文档，确认是否和预期契合

想清楚目标，才是有效的沟通
文档是一种沟通方式。沟通的核心是达成目标。有了目标，文档才能用核心主线。
那么，写文档的目标是什么？换句话说，你希望对方看到文档能导向什么决策？
当xx看到文档后，投入更多资源，因为我要去做这件事情很重要；
当xx看到文档后，把这块业务砍了，因为我证明了这件事情没有价值；
当xx看到文档后，找谁来帮我，因为只有这样才能解决当下的问题。
如果文档的组织没有目标，只做现状阐述，罗列信息，每个人看完文档会形成分散的结论，可能会使决策人形成错误的认知，导向错误的决策方向。

ps：是套路，但是是好的套路。 写文档不是罗列信息，这里owner要有判断力，是提供决策线索的。基于这件事有自己的判断=>论点，再下钻是基于论据来支撑论点的。当你看到ta的论点是：证明这件事没有价值，下面会有论据证明为什么没有价值，这里是能够自证的，而不是忽悠人的套路。

第二部分：信息组织的关键要素

【视角】需求视角&供给视角，决定要表达什么
从需求视角思考如何组织文档
这里参考：像打造产品一样写文档
看文档的角色是什么，不同角色关注什么，不同角色对信息密度的要求是什么

不要写标题，要写观点
标题不要罗列，而是能够表达所有观点。检验把文档写清楚的方式，是通过阅读标题就能够了解清楚主要的观点内容。
观点展示在段头，便于读者的信息获取：
- 如果清楚，了解到关键的结论信息，阅读结束；
- 如果存疑，继续下钻，确认是否有足够的论据来支撑文档的观点和结论。

【框架】怎样做逻辑拆分，把事情讲清楚
写文档框架的时候，核心是在做逻辑拆解，应该用哪些维度拆解，能表达清楚这个文档。

通用逻辑：问题&现状&to do 
常用于把一件事拆解清楚

业务逻辑：拆解业务增长公式
举例：如何拆解直播业务？把直播拆成几个重要的事情：DAU x 渗透率 x 付费率 x 付费ARPU
[图片]
按照业务逻辑拆解出的核心指标，介绍进展情况，详细归因以及后续 to do。
当拆解出了指标，要思考那些事情是服务这个指标的，所以这些事情都应该和核心指标有关。

所以，整体业务逻辑：
- 启动期：探索各场景最优体验和策略，优化曝光点击，挑选主播。重点关注渗透和转化。
- 增长期：场景体验稳定，加强渗透和转化。增大开播量，重点促进模式成熟和付费率渗透。
- 成熟期：场景、付费率稳定，持续探索。重点关注ARPU和生态泛化，横向拓展规模。

【判断】数据&用研有偏差，要有判断力

数据偏差：不要只相信数据，要关注偏差
- 数据是有偏差的，不同的统计方法会有偏差，缺少其他问题的考量也会有偏差。
大家都听过幸存者偏差，但不同场景下，看到核心因素的难度也是不同的；
- 没来的请举手
- 春运列车上采访是否买到票
- 公园里面随机采访老年人身体状态
- 仅根据用户反馈群里的意见修改产品
  - 来反馈的不一定是最严重的问题，因为发现最严重问题的那批人可能已经弃用产品了，根本不可能给你反馈
  - 举个极端例子，如果用户反馈的都是极端例子，如果用户反馈的都是细枝末节的体验问题，但其实产品策略大方向有问题，导致产品市场天花板大大受损，这种问题才是更加本质的，决定产品天花板甚至生死。

- 对同一数据的不同描述，也会引发不同的判断框架
术后一个月的存活率是90%，术后一个月病人大概有10%的概率死亡；
两组医生分别听完这两个意思完全相同的不同描述，为病人采取采取手术治疗的概率有巨大差异；

用研偏差：结合用户行为分析，而不是只听用户怎么说
用户研究的感性认知，加剧了产生偏差的可能性。
用户研究很有感染力，产生偏差的时候，容易让人相信
你以为用户说的，和用户以为自己说的，以及别人听用户说的可能都不太一样

因此，要先有业务逻辑和观点，在组织数据和用研的信息，整理出支撑观点的相应论据。而不是先有数据和用研，从中找信息拿来用。关键的是，进行业务拆解的时候要有判断力。

不要围绕数据和用研，而是要围绕观点。

灵魂拷问x3：为什么要做这件事？谁想看？为什么要看？
- 对业务负责人而言，收集业务信息，了解各方向进展&问题，并做出合适的判断，在合适的时间点提供资源，促进业务的快速推进。
- 对各方向业务线leader而言，梳理近期的重要进展和问题，是沉淀、总结和复盘；且能互相了解其它各方向的重要事项同步，促进各业务线之间的协同配合；
框架模版：基于业务逻辑整合信息
- 提取核心指标：明确该业务的核心指标，看数据变化和趋势，解释并归因；
- 拆解业务模块：
  - 模块进展同步：确认和核心指标相关的若干业务模块，看该模块核心数据，关注变化和进展；
  - 关键项目同步：「协同确认」、「资源瓶颈」、「决策要素对齐」、「调研结论」可同步；

第四部分：业务关键问题材料怎么写
关键材料，如何对齐 => 关键材料对齐方法论 
直播开始组织对业务关键问题进行密集讨论和对齐，背景参考：直播关键问题讨论playbook

预期&目标：对齐关键问题认知，做好沉淀并做好后续工作和合作
所以，每个议题预期有怎样的答案？最终要形成什么样的材料？
要形成的材料是阶段共识和具体的操作规范（最佳实践），沉淀下来指导后续的工作和合作
材料形成过程：有观点，论据=>通过补充和修订，达成共识=>以共识为指导原则，补充最佳实践和指导意见

搞定了预期和目标，开始思考和写作
写作过程是：分析问题=>确认框架=>论据补充=>确认观点

分析问题：要解决的是什么问题？
- 写作前，思考和交流尤为重要：和提问者和问题相关方沟通；
  - 谁提的，为啥提？
  - 谁和问题相关？谁能协助解答问题？
  - ta们的诉求是什么，想要什么答案？
结合场景问题，相关方是谁(abcd)，为什么要问，预期什么答案，得到答案后对自己有什么作用？
这里引用「像打造产品一样写文档」需求视角的表格
需求视角：想想你的受众是谁，了解他们的期望值
目标是什么，解决的问题是什么
重视思考和交流这一步，不要上来就写，更重要的是「多想」和「多问」
不能局限于文字表面，分析问题要考虑多立场，站在不同角度提炼的观点

确认框架：怎样做逻辑拆解，把这件事情讲清楚
先形成故事线 = 文档提纲
- 观点明确，直接列提纲500字故事线；
- 观点不明确，先确定一个大概方向，尽可能深入拓展，梳理出几个相关立意，通过思考/阅读材料/交流，确定核心主题和观点

故事线怎么列：先抽象成观点，再演绎是否适用
- 基本要求：核心传递清楚观点，为什么有这些观点，以及对后面的工作有啥更好的实践
- 怎么做：先列通用逻辑（现状以及to do），补充信息，最终把通过逻辑变成故事线
- 具体过程：收集信息&讨论 => 初步观点和框架形成 => 基于观点来演绎，看是否有论据支撑观点，是否适用所有的情况 => 可能会遇到问题（再回到收集信息和讨论）=> 重新调整&修正 => 最终抽象和总结，形成完整信息。
整体是归纳和演绎的过程 = 先抽象形成的是观点，再演绎看是否适用
在此产出的是材料框架，也会形成了核心观点
强烈建议在框架阶段，involve上级对1-2次，积极提问和确认
确认故事线的逻辑是否正确，思路方向是否需要纠偏

论据补充：解释说明你的核心观点
- 文章结构：谨记金字塔结构（参考第二部分）
- 内容组织：从现有数据/历史信息中找论据（参考第二部分）
有观点+观点的解释说明后，一定还要有最佳实践
现有概述的定义问题是什么，再解释为什么有问题，接下来是最佳实践；

确认观点：整体review&纠偏
- 整体：是否有整体的核心观点？是否有效表达完整的观点？
- 部分：分论点清晰，分论点每一个论点的论证要合理和明确，有足够的数据/论据支撑
- 整体和部分/部分之间：分论点之间是否有逻辑关系（总分/递进/并列），是否可以支撑核心观点？全篇内容是否能清晰的解释前面的概论总述？
