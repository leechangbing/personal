[起点]：理解两种不同的文档视角：需求视角 vs. 供给视角
需求视角：想想你的受众是谁，了解他们的期望值
目标是什么，解决的问题是什么
供给视角：把我做了什么展示给你看
特点：文档的整体结构和二级部门的组织架构高度神似，各个二级部门负责写一小块，最后找一个PMO当裁缝，拼成一起；
陷阱：很容易失去重点，变成工作流水账，各打五十大板，春晚式汇报；
缺点：对不熟悉你部门架构的人来说，这些二级部门之间的耦合关系和业务逻辑，理解成本有很高，很容易听晕，又不好意思现场提问；
优点：事无巨细，面面俱到；

公司双月会/季度会：需求视角优先，大家各取所需；
内部工作/review会议：供给视角优先，查漏补缺；
【痛苦的反思时刻来临】：过去无数次的文档里，有没有可能把上面的答案选反；

双月会的受众群体中的三种角色，无论是哪一种，有一个共同期望是想了解“业务的整体情况”，所以在需求视角中应该围绕着把业务本身说清楚、讲明白为出发点。实际上，只要你讲清楚了业务情况，这几种角色的其他需求，答案也是呼之欲出的。

[聚焦]：怎么把一块业务说清楚、讲明白？
解法：用2.5个维度来叙述业务
维度1：业务主线，概括性质的东西，偏粗线条；
维度2：从一个或几个维度对业务的break down，让大家看到业务增长/下降的归因；
维度2.5：选择一个最值得拿出来说的点，往下钻，展开来说，增加信息丰富度，传说中「万历十五年」的时刻，以小见大的时刻；
维度1：业务整体状况，如何在最短的时间内让大家了解这个业务的进展
- For 业务负责人：如果每天只有1分钟甚至30秒，你会关注那些指标和事情进展？
- For 三种角色：假想一下，有且只有三个问题，你会问关于这个业务的什么问题？
- 要求：简单直接，让人秒懂；把最重要的信息高度提炼，在保证信息量的同时，尽可能降低读者阅读理解的成本；
维度2：找到业务的增长公式，拆解开来看
深刻理解业务是起点，针对维度1里面的关键指标，把他们拆解为一级增长公式；

Performance = A * B * C * D

（这里的*，可以是加法也可以是乘法）

ABCD里，有一些是快变量，有一些是慢变量，在这个环节中，需要清晰的给受众指出，驱动业务当前发展的主要动力/阻力是什么？以及对应的后续方案是什么？

所以，一般的叙事线长成这个样子的---
performance达到预期，主要是因为A/B超出预期，C无明显变化，D明显低于预期；
A主要是做了...这些事情，后续打算加强；
B主要是因为....，后期打算加强....
C这个双月做了三件事，但是没有效果，后面打算不搞了，to do 是没有do；
D主要是出了...的bug导致没有达到预期，后续to do是...，所需要的支持...

简单干净，不拖泥带水，这样就ok了；

Q1：如何选择break down的角度？
关键的决策点在于：怎么切分才能反映出最真实的问题，就选择那个角度；所以实际的操作中，在最后呈现出来之前，都会先在桌子底下横竖狂切，直到找到最佳的业务观察角度；

Q2：为什么避免把增长公式拆分到-2甚至-3层级，譬如，把A再拆分为A1/A2/A3？
- 太复杂
- 看不懂，有理解成本
- 更重要的是，大家并不关心（潜台词：哦，那是你的分内事，你就自己内部去折腾这些A1/A2/A3吧）

Q3：偏定性的职能线、支持性业务是否可以用类似方式？
- 可以
- 偏职能线、支持性的工作，未必可以明显量化产出，但实际上最后你的产出也是可以分解为两个、三个动作，道理是一样的，如果你无法做出这些分解动作，很可能你对业务本身的理解还缺少一个“向上抽离”的动作，nothing is unbreakable。

维度2.5：深入下钻，以小见大
无论是维度1还是维度2，其实多少是会给人一种浮于水面的感觉，这里是一个放大镜，把某个点打开来看；
为什么说这个维度是「万历十五年」的时刻，就是需要从这个case里面以小见大，背后反应的是业务系统层面的问题和todo，譬如：
  - 一个bad case的分析，需要提炼到反映出的安全漏洞层面还有哪些不足，后续的to do是什么，需要谁支持配合；
  - 之前对小说领域的分析，得出的结论是这是个赚快钱的事，结论有两个：一是让穿山甲持续提升变现能力，让子弹飞一年；二是严控加粉类小说，政策拉起防止套利。这基本上是从现象出发，最后上升到政策、平台能力这个落脚点；
    - 鲁班的事故，光说损失多少没有什么意思，需要反思到对产品风控体系的重新审视，和后续的思路打法；

[释疑]：如何精益求精？

三种角色的个性化需求怎么办
从上面2.5个维度中说清楚了业务，就会发现，这些问题的答案都可以见缝插针的放到各个角落里，譬如：在各种to do里，说清楚你下一步的工作重心，以及这些重心如果实施开来，所需要的公司层面的资源支持和团队配合，如果是下个双月就落实的，标准成【下双月OKR】。
另一种方式更加简单直接，在讲清楚业务本身的facts之后，后面单列出来一个section，讲清楚公司层面讨论的问题和需要的支持。

OKR怎么办
在做完以上那么多工作以后，如果对于下个双月/季度的重点还是不清楚，写不出OKR，其实需要把上面的过程再走一遍，很怀疑是不是把业务整体真的看的足够清楚了？
符合预期的事情，都是你好我好大家好，无非是个重设目标的事情；不符合预期的事情，需要重点关注，用OKR做目标管理。一个观察是：
- 可以立竿见影的事情，是快变量，通常会有很多人盯，而且有很多一线的员工在天天盯着，这些快变量，因为是短期业务增长的动力，反而不太容易出问题，即使出了问题之后修复的速度也会很快；
- 容易出问题的是那些影响长期变量的慢变量，短期内未必马上产生效力，是需要更高层级的员工来特别关注，用N个OKR来突破，譬如说组织问题、效率问题、安全问题、合规问题等；
- 一线员工除了关注日常的大量快变量之外，需要继承一部分来自更高层级员工的慢变量工作；

关于会议的主持人
- 角色的人设：业务代言人，代表业务和公司层面的一次沟通和对话；
- 需要对业务有全局认识，是文档这个“产品”首席架构师，而不是裁缝（拼凑文档）；
- 需要有会议现场的总控能力，尽量减少传话筒的角色，字节回答问题；

其他Tips
1. 使用小白语言，尽量减少术语，说人话，尽量降低读者/观众的理解成本，让实习生都能听的懂；
2. 控制篇幅，保持精简，在一万字以内，信息冗余的情况远远多于信息不足的情况；
3. 格式错误、图标滥用会让你很不专业；
4. 语法错误、错别字会让你显得不用心和不专业；
