背景
在视频推荐场景中，对于播放时长怎么预估是一个比较棘手的问题，比如最早的YouTube采用weighted loss方式预估播放时长（揭开YouTube深度推荐系统模型Serving之谜），又比如快手提出的对不同时长区间采用分位点建模（KDD2022｜快手：基于因果消偏的观看时长预估模型）。播放时长是一个连续性目标，如果采用线性回归来建模，会导致模型会被长视频带偏。
目标
play_n：表示是否播放超过了n秒；可以定义多个时长目标：play_10、play_30、play_50、play_80、play_120、play_180、play_300，这种播放区间可以用分位点来划分。
训练
定义p(10) = 播放10s以上的概率，p(30|10)=播放10s后播放30s的概率，p(50|30)=在播放30s后播放50s的概率，以此类推；
loss_10 = p(10)*play_10 + (1-p(10)) * (1-play_10)
p(30) = p(30|10) * p(10)
loss_30 = p(30) * play_30 + (1-p(30)) * (1-play_30)
p(50) = p(50|30) * p(30)
loss_50 = p(50|30) * p(30)
loss_50 = p(50) * play_50 + (1-p(50)) * (1-play_50)
以此类推，以贝叶斯网络方式对80s、120s、300s等类似处理；
Loss = loss_10 + loss_30 + loss_50 + loss_80 + loss_120 + loss_180 + loss_300
Serving
预估时长=p(10) * 10 + (30-10) * p(30|10) + (50-30) * p(50|30) + ... + (300-180) * p(300|180)，此处的p(10)、p(30|10)、...、p(300|180) 是训练中多个目标sigmoid之后的概率。
讨论
问题1：这种方式预估的时长可能会很不准确。首先p(10)*10并不能代表<10的那部分时长预估值，其次预估时长方案中p(10)对最后预估值的贡献很小，相反p(300|100)影响很大，导致p(300)的一点波动和不准确，就会放大到最终的时长预估值，导致对低时长的样本预估非常不准确。
问题2:这就是有序回归吧，相当于把oridinal relation和conditional dependency建模了。
