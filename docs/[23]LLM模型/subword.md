2018年，大参数量的预训练模型一个接着一个出现，为自然语言处理带来了突破性的进展。在这些预训练模型中除了ELMo，其他模型都使用了transfromer结构，原因是Transformer结构使得在GPU上进行大规模训练成为可能，而模型的参数量越来越大，达到十亿甚至百亿级别。
我们都了解一种基本的tokenization方式，就是将每一个单词都视为一个token，然后对其编号。这种编码方式非常符合人类语言习惯，因此人类语言也经常以单词为单位进行交流，但这并不一定是最合理的编码方式。
一门语言中，通常有几万乃至几十万的单词数量。若使用这种编码方式，在语言模型预测的时候需要在这几万个单词的列表中计算概率分布，那样计算复杂度是非常恐怖的，而且过大的token列表也会十分影响到模型预测精准度。
在GPT-3中随着模型集成的不同国家的语言越来越多，模型的词汇列表势必会增长到一个非常可怕的数量级，该如何去处理它带来的矩阵内存占用和预测准确性问题呢？
因此，就需要一种编码方式大大降低token list，目前主流的subword算法主要包括BPE(Byte Pair Encoding)、Wordpiece、ULM(Unigram Language Model)。
BPE: Byte Pair Encoding
理解NLP最重要的编码方式 — Byte Pair Encoding (BPE)，这一篇就够了
初识BPE
BPE是一种简单的数据压缩算法，它在1994年发表的“A New Algorithm for Data Compression.”中被首次提出，一句话概括它的核心思想：BPE每一步都将最常见的一对相邻单位数据替换为该数据中从未出现过的一个新单位，反复迭代直到满足停止条件。
假设我们有需要编码的数据aaabdaaabac，其中相邻字节对（相邻数据单位在BPE中看做相邻字节对）aa最常见，因此我们用一个新字符Z替换它。我们现在有了ZabdZabac，其中Z=aa。下一个常见的字节对是ab，我们用Y替换它。现在我们有ZYdZYac，其中Z=aa，Y=ab。剩下的唯一字节对是ac，它只有一个，因此我们不对它编码。我们可以使用递归的方式对其进行迭代编码，用X替换ZY得到XdXac，其中X=ZY，Y=ab，Z=aa。它不能被进一步压缩了，因为没有出现多次的字节对了。如何将压缩的编码复原呢？反向执行以上过程就行了。
NLP实例
首先来明确明确一个基础概念：token可以理解为一个符号，就代表一个语言单位(就像单词、字符等)；tokenize的意思就是把句子或者长语料分成token。
BPE确保最常见的词在token列表中表示为单个token，而罕见的词被分解为两个或者多个subword tokens，因此BPE也是经典的基于subword的tokenization算法。
假设我们有一个语料库，其中包含单词（pre-tokenization之后）——old、older、highest和lowest等，我们计算这些词在语料库中出现的频率，假设这些词的频率如下：{"old": 7，"older": 3, "finest": 9, "lowest": 4}；在每个单词的末尾添加一个特殊的结束标记"</w>"，{"old</w>": 7, "older</w>": 3, "finest</w>": 9, "lower</w>": 4}；接下来我们将每个单词拆分为字符并计算它们的出现次数，初始token将是所有字符和"</w>"标记的集合。
BPE算法的下一步是寻找最频繁的字符对，合并它们并迭代执行，直到达到预设token数限制或者迭代限制。
合并字符可以让你用最少的token来表示语料库，这也是BPE算法的主要算法，即数据压缩。为了合并，BPE寻找最长出现的字节对。在这里，我们将字符视为与字节等价，这是针对英语的用法，其他语言可能有所不同，我们将最常见的字节对合并成一个token，并将他们添加到token列表中，并重新计算每个token的概率。
编码和解码
对于给定的示例要解码，需要简单地将所有token连接在一起以获得完整的单词。例如编码序列["the</w>", "high", "est</w>", "range</w>", "in</w>", "Seattle</w>"]，我们将其解码为["the", "highest", "range", "in", "Seattle"]而不是["the", "high", "estrange", "in", "Seattle"]，因此"est"中存在"</w>"token。
对于新数据进行编码的过程还是比较简单的。然而，编码本身计算复杂度比较高。假设单词的序列是["the</w>", "highest</w>", "range</w>", "in</w>", "Seattle</w>"]。我们将遍历我们在语料库中找到的所有token——从最长到最短，并尝试使用这些token替换给定单词顺序中的子字符串。最终，我们将遍历所有token，并且我们的子字符串将被替换成我们token列表中已经存在的token组合。如果留下几个子字符串（在训练中没有看到的词），我们将用unknown token替代。
我们常用的语言模型词汇列表还是很大的，但仍有可能出现不在里面的单词。在实践中，我们将tokenize好的单词保存在字典中，对于未知的新词，我们应用上述方法对新词进行tokenization，并将新词的token添加到token字典中备用。
是不是贪心算法？
为了以最有效的方式构建语料库，BPE在迭代的时候迭通过比较每一种token的频率大小来穷尽每一种可能，因此它遵循一种贪婪策略来尽可能来取得最优的解决方案。
无论如何，BPE是使用最为广泛的tokenalization算法之一。尽管贪婪，但它有良好的性能，并被作为机器翻译等主流NLP任务的首选tokenize方法之一。
WordPiece
Google的BERT模型在分词的时候使用的是WordPiece算法。与BPE算法类似，WordPiece算法也是每次从词表中选择两个字词合并成新的子词。与BPE的最大区别在于，如何选择两个字词进行合并：BPE选择频数最高的相邻字词合并，而WordPiece选择能够提升语言模型概率最大的相邻字词加入词表。
假设句子S=(t_1, t_2, t_3, ..., t_n)由n个词组成，t_i表示子词，且假设各个子词之间是独立存在的，则句子S的语言模型似然值等于所有子词概率的乘积：
$$logP(s)=\sum_{i=1}^n logP(t_i)$$
假设把相邻位置的x和y两个子词进行合并，合并后产生的子词记为z，此时句子的似然值的变化可以表示为：
$$logP(t_z)-(logP(t_x)+log(P(t_y))=log(\frac{P(t_z)}{P(t_x)P(t_y)})$$
从上面的公式，很容易发现，似然值的变化就是两个子词之间的互信息。简而言之，WordPiece每次选择合并的两个子词，他们具有最大的互信息值，也就是两个子词在语言模型上具有较强的关联性，它们经常在语料中以相邻方式同时出现。
ULM：Unigram Language Model
与WordPiece一样，Unigram Language Model(ULM)同样使用语言模型来挑选子词。不同之处在于，BPE和WordPiece算法的词表大小都是从小到大变化，属于增量法。而ULM则是减量法，即先初始化一个大词表，根据评估准则不断丢弃词表，直到满足限定条件。ULM算法考虑了句子的不同分词可能，因此能够输出带概率的多个子词分段。
对于句子S，$$\vec{x}=(x_1，x_2, ..., x_m)$$为句子的一个分词结果，由m个子词组成，所以当期分词下句子S的似然值可以表示为：
$$P(\vec{x})=\prod_{i=1}^{m}P(x_i)$$
对于句子S，挑选似然值最大的作为分词结果，则可以表示为
$$x^*=arg\max_{x\in{U(x)}}P(\vec{x})$$
这里$$U(x)$$包含了句子的所有分词结果。在实际应用中，词表大小有上万个，直接罗列所有可能得分词组合不具有操作性，针对这个问题，可以通过维特比算法得到$$x^*$$来解决。
那么怎么求解每个子词的概率$$P(x^*)$$呢？ULM通过EM算法来估计，假设当前词表V，则M步最大化的对象是如下似然函数：
$$L=\sum_{s=1}^{|D|}log(X^{s})=\sum_{s=1}^{|D|}log(\sum_{x\in U(X^{s})}P(x))$$
其中，|D|是语料库中语料数量，上述公式的一个直观理解是，将语料库中所有句子的所有分词组合形成的概率相加。
但是，初始化时，词表V并不存在。因此，ULM算法采用不断迭代的方式来构造词表以求解分词概率：
1. 初始时，创建一个足够大的词表。一般，可用语料中的所有字符加上常见的子字符串初始化词表，也可以同步哦BPE算法初始化；
2. 针对当前词表，用EM算法求解每个子词在语料的概率；
3. 对于每个子词，计算当该子词被从词表中移除时，总的loss降低多少，记为该词的loss；
4. 将子词按照loss大小进行排序，丢弃一定比例loss最小的字词(例如20%)，保留下来的子词生成新的词表。需要注意的是，单字符不能被丢弃，这是为了避免OOV情况；
5. 重复步骤2到4，直到词表大小减少到设定范围。
可以看出，ULM会保留那些以较高频率出现在很多句子的分析结果中的子词，因为这些子词如果被丢弃，其损失会很大。
