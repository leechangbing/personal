# 微调(fine-tuning)
## 基础概念
微调（Fine-tuning）是将预训练模型适配到下游特定任务的关键技术，根据是否更新全部参数、引入新结构、数据规模等因素，微调方式可以分为几大类：
- 全参数微调(Full Fine-tuning): 解冻整个预训练模型的参数，在下游任务进行端到端训练
    - 优点：通常性能最好，能充分适配下游任务；
    - 缺点：计算和显存开销大，小数据集容易过拟合；
    - 适用场景：计算资源充足，任务数据量较大时候；
- 部分微调(Partial Fine-Tuning): 
    - 做法：仅仅微调模型的一部份层（例如只微调最后基层transfromer），其余冻结；
    - 原理：底层学习通用特征（例如语法、边缘），高层学习任务特有特征；
    - 优点：节省资源，减少过拟合风险；
    - 缺点：可能缺失部分性能；
- 高效参数微调(Parameter-Efficient Fine-Tuning, PEFT)
    - 核心思想：在保持预训练模型大部份参数冻结（不更新）的前提下，仅仅引入少量可训练参数进行任务适配，从而降低计算资源、存储和内存开销；
    - 常见方法：
        - Adapter: 在原有层插入小型可训练模块，例如在Transformer层中插入小型神经网络模块，通常为两层MLP，只训练这些Adapter模块，主干模型冻结；
        - LoRA(Low-Rank Adaption): 低秩适配，将权重更新表示为低秩矩阵分解，$\Delta W=A*B$, 其中A和B是低秩矩阵，冻结原始权重只训练A和B；
        - Prompting Tuning / Prefix Tuning: 在输入前添加可学习的软提示（soft prompts）向量；prefix tuning在每一层都加前缀，prompt tuning通常只在输入层加；类似于指令微调，但参数有限；
        - BitFit: 仅微调偏置项，其它参数冻结，极其轻量，但效果有限；

## 全量微调(Full Fine-Tuning)VS参数效率微调(Parameter-Efficient Fine-Tuning, PEFT)
- 全量微调的计算成本：调整大型预训练语言模型，以及通过全量微调来适应专门的下游任务，看起来是一种直接的方法，然后这个过程中需要更新模型的每一个参数，因此会带来大量的计算成本。内存需求：GPU瓶颈，全量微调需要同时在GPU内存中存储多个大型张量：
    - 模型权重（model weights）： 参数（parameter）本身构成了基础的内存需求，对于一个有N个参数的模型，以标准32位浮点精度（FP32）存储需要4N个字节。即使使用FP16或者BF6位格式的混合精度，仍然需要2N个字节。对于GPT-3拥有175B参数的模型，在FP32下需要700GB内存，FP16/BF16下需要350GB内存，远远超过普通GPU的容量。
    - 梯度（$\Delta W$）：在反向传播（back-propagation）过程中，会为每个参数计算梯度。这些梯度通常会与模型权重具有相同的维度，并需要相同的内存（如果对梯度采用混合精度，则FP32下额外需要4N字节，FP16/BF16则需要2N个字节）。
    - 优化器状态：Adam或者AdamW等现代优化器会维护状态信息，以调整每个参数的学习率。例如Adam会为每个参数存储两个矩：第一矩（动量）和第二矩（方差）。如果这些矩以FP32存储，将会额外增加8N字节（每个矩4N个字节）。在FP32中使用AdamW时，参数、梯度和优化器的总内存可以迅速增加到4N+4N+8N=16N字节。如果矩采用量化方案（quantization），则会更少。
    - 中间激活值：前向传播位每个层生成激活值。在反向传播过程中需要激活值来计算梯度，激活值消耗的内存取决于批量大小、序列长度、模型隐藏维度以及层数。对于大模型和长序列，激活值会消耗大量内存，有时候甚至会超过权重和优化器状态的内存。激活检查点等技术可以通过在反向传播时重新计算激活值而不是存储他们来减少内存消耗，但会增加计算时间（通常为30%）。
    - 在微调中等规模参数的模型（例如70亿到130亿参数），需要配备大内存容量（例如40GB或80GB）的高端GPU，通常需要跨多个GPU进行分布式训练设置，但会增加通信开销和复杂性。
- 参数效率的必要性：对于一个拥有70亿、700亿甚至上千亿参数，完全微调需要：
    - 庞大的计算资源：在反向传播过程中，计算梯度和数十亿参数更新是计算密集型；
    - 过高的内存需求：存储模型权重、参数梯度、优化器状态以及中间激活值会消耗大量的GPU内存（VRAM）。一个700亿参数的模型，即使采用混合精度（16位浮点数），仅参数、梯度和优化器状态就需要56GB（2N+2N+4N）的VRAM。
    - 繁琐的存储和部署：如果需要哦为一个基础模型适配不同的下游任务，完全微调会导致位每个任务生成一个完整的、数GB的模型副本。例如位十个从相同700亿参数基础模型派生出来的不同下游任务维护140GB模型文件，仅仅调整后的权重就占用了1.4TB。
    - 此外，更新全部参数还有灾难性遗忘的风险。
- 为什么效率并非可有可无？完全微调的局限性使得，有效调整LLM但只修改部分参数变得十分必要。主要目标包括：
    - 大幅减少计算和内存：使得微调在要求较低的硬件上（例如，单个GPU或者较小的硬件上变得可行）；
    - 实效高效多任务调整：允许单个预训练模型实例通过只加载少量特定任务的参数来服务多个任务，而不是加载整个模型副本，极大简化了部署并显著降低了存储开销；
    - 减轻灾难性遗忘：通过冻结原模型绝大多数参数，只调整一小部份，PEFT方法通常会比完全微调更能保留模型的通用能力；
    - 促进更快实验：较低的资源需求允许在开发和测试新任务调整时进行更快的迭代周期；
- 参数效率总结：
    - PEFT方法通过策略性的添加或者修改部分参数（通常小于总参数的1%），同时保持预训练模型的大部份冻结状态来实现这一点。
    - 基本假设与LoRA等方法有关，**特定任务所需要的调整通常存在于一个低维子空间中**，意味着模型权重所需要的变化，即更新矩阵$\Delta W$，通常可以通过一个低秩矩阵有效近似，这比完整的$\Delta W$需要少的多的参数来表示。


## 低秩适配（LoRA）详解
- 核心假设：
    - 模型权重在适配过程中产生的变化$\Delta W$具有较低的内在秩，意味着$\Delta W$ 可以通过两个小的多矩阵A和B的乘机来有效近似。
    - 在将大型预训练模型适配到特定下游任务时，权重矩阵的变化不需要涵盖原始权重矩阵的全部维度，而是主要发生在一个低维子空间中，其"秩"可能会显著小的多。
    - 通过假定任务特定的适配存在于一个低秩子空间中，LoRA用低秩因子A和B代替$\Delta W$的直接优化，同时保持原始权重W不变。
- 数学表达：
    - LoRA提出了一种特定的数学结构，其设计理念是基于适应过程中权重更新具有低秩的假设，旨在提升参数效率。在标准微调中，通过添加一个增量矩阵来更新预训练权重，从而得到适配后的权重。
