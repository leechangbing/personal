1. SQL基础
1.1 简介
1.  数据库：
  1. 永久数据的一个或多个大型结构化集合，通常与查询和更新软件有关。简单的数据库可以是一个包含许多记录（record）的文件，每个记录包含相同的字段（field）集合，每个字段具有特定的固定宽度。 
  2. 数据的结构化集合，以表的形式存储数据集合，包含有许多记录，每个字段有固定宽度。数据库通常只存储数据，前端程序负责处理数据。
2. 关系型数据库：
  1. 包含的数据被组织和互相连接到一起；
  2. 优点：数据检索的快速和高效性，允许不同的数据互相关联，且安全性；
  3. 结构：数据库，表，字段，对象
  4. 关系型：一个表中的数据和另一个表中的数据存在某种类型的链接
3. 数据库管理系统：DBMS，管理一个或多个数据库的全部程序
4. 结构化查询语言SQL：SQL是一种声明性语言，明确告诉它想要什么；创建数据库，并定义结构；查询数据库；控制数据库安全

  - 创建数据库：Creat database mydb;

  - 查询数据库：
    - SELECT column_name； --statement, 语句
    - FROM table_name； --clause, 子句
    - WHERE condition； --condition, 条件
- 数据类型：为什么要有不同的数据类型？原因在于效率，若要知道处理的数据类型之后，能够节省存储空间总量并提高访问速度。常见类型
  - Char：一个字节
  - Varchar: 一个字节
  - Integer：四个字节
  - Real: 四个字节
  - Date: 四个字节

- 程序设计
  - 获得并分析数据需求
  - 逻辑划分数据
  - 选择正确的数据类型
  - 使用主键
- 输入信息
  - 插入数据：Insert into table_name (column_names) values (data_values)
  - 更新数据：
    - Update table_name

  - 查询数据：Select column_names from table_name where condition;
  - 使用别名：As或者空格
  - 运算符优先级：（）；NOT；AND；ALL, ANY, BETWEEN, IN, LIKE, OR, SOME
1.3 SQL操作数据
- 基础操作
  - 算数操作：+ - * /
  - 数学函数：ABS(), Power(expression, power_raise_to), Sqrt(), RAND()
  - 舍入函数：CEILING() 向上取整， FLOOR() 向下取整， ROUND()四舍五入
  - 字符串函数：
    - Substring(string, start, length)
    - Upper() 大写转换
    - Lower() 小写转换
    - Reverse() 反转
    - TRIM() 删除开始或结尾中不想要的字符（空格）
    - Length() 长度
  - 日期函数：Month（），Day（），Year（）
  - 数据类型转换：CAST(expression As data_type)
  - NULL: 表示未知数据，而不是任意特定值
  - 数学：如果null出现在任何SQL数学函数中，结果总是NULL
  - 字符串：concat()或+拼接之后结果也为NULL
- 分组聚合
  - 一般性的select：仅仅返回一些记录的列表，即满足条件的数据，而不是汇总或概述
    - 分组函数：将数据分为不同的组，并将分组中的数据作为整体返回
    - 聚合函数：总结数据，例如求平均值，统计个数等
  - Group By：该子句根据参数进行分组
    - 聚合：Count(), Sum(), Max(), Min(), AVG()
    - Group by必须要放在from和where之后，需要分组的列都要放在group by列表中，使用逗号隔开。
  - 综合使用Having和Group By, Having和Where类似，Having是针对每一个分组，过滤不满足条件的分组，Where是针对每一条记录，过滤不满足条件的记录。
- 联合函数
  - 内部联合
    - 语法：name_of_left_table INNER JOIN name_of_right_table on condition
    - 条件：等值联合，例子：A.id = B.id；不等值联合，例子：A.date > B.date
  - 多个表联合
    - 显式调用INNER JOIN：A INNER JOIN B on (A, B) INNER JOIN C on (…, C)
    -  使用WHERE子句来联合表：多个条件中不仅具有一个，也可以多个一起
  - 交叉联合（克罗内克积）：最基本的联合，不存在ON子句，联合中列举的所有表中的所有记录都会返回
  - 自联合：一个表联合到它自己，而不是其它表，与子查询结合更有意义，与其它联合语法一致，区别在于赋予表别名。
  - 外部联合：要求包含在联合中的两个表必须具有匹配的记录，即ON子句为真，不需要两个表具有匹配的记录。
  - 左外部联合：左边表中的所有记录都被包含在返回结果中，即时不满足ON子句中的条件，不匹配是返回NULL值。
  - 右外部联合：右边表的所有记录都会出现在返回结果中。
  - 利用UNION组合结果
    - Union可以将两个或多个select查询结果联合到一个结果中
    - 每个查询产生相同的列数目
    - 列的数据类型相同
    - 默认情况下，union合并两个查询，仅包含唯一的记录，需要使用ALL语句

2. 数据库设计
2.1 特性
1. 事务：在执行SQL语句时，某些业务要求，一系列操作必须全部执行，而不能仅仅执行一部分。由于某些原因，一部分被成功执行，另外一部分失败，则全部被撤销。
2. 数据库事务：把多条语句作为一个整体进行操作的功能，数据库事务可以确保事务范围内所有操作都可以全部成功或全部失败。
3. 数据库ACID特性
  1. Atomic: 原子性，将所有SQL作为源自工作单元执行，要么全部执行，要么全部不执行；
  2. Consistent：一致性，事务完成后，所有数据状态一致，A账户减少100，B账户一定要增加100；
  3. Isolation: 隔离性，如果有多个事务并发执行，每个事务做出的修改必须要与其他事务隔离；
  4. Duration：持久性，对数据库的修改被持久化存储；
对于单条SQL语句，数据库系统会自动将其作为一个事务，即“隐式事务”；要手动将全部SQL作为一个事务执行，使用Begin开启事务，Commit提交事务，这种称为“显示事务”。
2.2 隔离
若两个并发执行的事务，涉及同一条记录的时候，可能会因为数据的不一致性带来脏读，幻读等数据问题。数据库提供了四种隔离等级，有针对性地选择事务的隔离级别，避免数据不一致的问题，分别对应可能出现的数据不一致情况。
1. Read Uncommitted:隔离等级最低的事务等级，在这种情况下，一个事务会读到另一个事务更新后为提交的数据，如果另一个事务回滚或者操作失败，那么当前事务读到的是就是脏数据，这就是脏读（dirty read）。
2. Read Committed，可能会遇到不可重复度“Non repeatable read”问题。不可重复读是指，在一个事务内，多次读取同一个数据，在这个事务还没有结束时，如果另一个事务恰好修改这个数据，那么第一个事务两次读取的数据可能不一致。
3. Repeatable Read: 可能会遇到幻读（Phantom Read），幻读是指在一个事务中，第一次查询某条记录不存在，但是当试图更新这条记录的时候，竟然能够成功，在此读取同一条记录的时候，它就神奇的出现了。（另外一个事务插入了该条记录）
4. Serializable：最严格的隔离等级，所有事务依次执行，因此脏读，不可重复度，幻读都不会出现。安全性得到提高，但是效率会有所下降。默认隔离等级为Repeatable Read。
2.3 约束
确保数据的有效性，第一时间内防止不正确的数据，声明约束，限制进入字段的数据；约束类型：NOT NULL; UNIQUE; CHECK; PRIMARY KEY; FOREIGE KEY
- NOT NULL
  - NULL数据类型与没有数据不同，它表示未知数据；
  - NULL会对查询造成问题，很难对具有NULL值的列进行排序；
  - 所有的NULL值都一样；
- UNIQUE约束
  - 防止一个特定的列有两个记录具有一致的值；
  - 可以对一个表添加多个约束，只要每个约束具有不同的名称，使用逗号隔开；
  - 创建table时，添加UNIQUE约束；
  - 使用alter table语句，修改约束
- CHECK约束：
  - 检查输入到记录中的值是否满足一个条件，如果条件为假，则违反约束；
  - 例子：Age int CHECK (age>=0)
- 主键和PRIMARY KEY约束
  - PRIMERY KEY约束是UNIQUE和NOT NULL约束的组合，多个列也可以作为主键
- 外键和FOREIGN KEY约束
  - 外键是访问另外一个表中的主键的列；
  - 主键和外键创建了不同表中的相互关系
2.4 数据库高级设计
- 目标：
  - 改进数据库的设计内容，使数据库更易于管理，具有更高的效率，以及限制无效数据输入
- 标准化
  - 由一系列指导仿真组成，创建结构完美的数据库。指导仿真被分为多种“范式”，它可以考虑为格式，或者数据库结构的组成方式。
  - 过多的标准化能够是的数据库的访问速度变慢，数据库变得复杂，范式的目标是为了组织数据库的结构，使得它符合第一范式规则，然后是第二范式，最后是第三范式。
- 第一范式
  - 定义数据项，即数据名称和数据类型
  - 确保没有重复的数据项
  - 确保存在一个主键
- 第二范式
  - 主键是记录的唯一表示符，第二范式要求主键中任意列没有局部相关性，例子：
  - Film ID: film name
  - Actor ID: actor name, date of birth
- 第三范式
  - 最小化数据冗余和提高数据库效率，不过降低空间占用和数据冗余量，代价是减低数据库的效率，尤其是获取数据和插入数据的速度；
  - 所有非主键字段都依赖于主键； 
    - 例子1：街道名，城市名，州名，邮编，理论上只要有邮编和街道名即可
    - 例子2：社会保险号码和人名，二者之间不存在直接相关性
  - 社会保险号码和名字之间的相关性，邮编和地址之间的相关性，传递相关性；
    - 消除传递相关性好处：降低数据重复量，使得数据库变小；保证数据完整性；
    - 消除传递相关性坏处：增加了复杂性并且降低了效率效率降低，花费更多时间检索数据；
2.5 利用索引加速查询
- 索引：一种特殊的查询表，数据搜索引擎可以使用它来加速数据检索，也组织数据库存储数据的格式；加速了数据检索，却减缓了数据的输入速度，例如INSERT语句；创建索引需要CREAT INDEX语句，允许指定表和需要索引的单个列和多个列，允许指定索引是升序还是降序排列；
- 语法：
-- 默认升序排列
CREAT INDEX <index_name>
ON <table_name> (<column_names>)

-- 删除
DROP INDEX <index_name> ON <table_name>

-- 例子
create union index name_index
on memberdetails (last_name DESC, first_name)
- 总结：
  - 标准化：定义数据项，主键相关性，最小化数据冗余
  - 约束确保数据完整性
  - 索引加速数据查询

3.2 Hadoop介绍
Hadoop是一个分布式系统基础架构，由Apache基金会开发，目前有Yahoo是最重要的贡献方。Hadoop实现了一个分布式文件系统（Hadoop distributed file system, HDFS），用户可以在不了解分布式系统底层细节的情况下开发应用程序，充分利用集群运算和存储。
- Hadoop特点：
  - 高扩容能力：可靠存储和处理千兆字节（PB）数据；
  - 低成本：通过普通机器组成的服务器集群来分发以及处理数据，节点可达数千个；
  - 高效率：通过分发数据，Hadoop可以在数据节点上并发处理；
  - 高可靠性：Hadoop能够自动维护数据的多分复制，并且在失败后自动重新部署计算；
- Hadoop家族：
  - Pig，Hive，HBase，Map Reduce，HDFS，Core，Avro，Zookeeper，Chukwu
- HDFS
  - 一种用于Hadoop应用程序的主存储系统，也是一个高容错系统，适合部署与廉价机器上，HDFS能够提高吞吐量，非常适合大规模数据集上的应用；
  - HDFS为了可靠性创建了多份数据块的复制，并放置在服务器集群的节点上，Map Reduce可以在节点上处理数据；
  - 由Name Node和Data Node组成，Name Node负责Name Space管理，Name Node保存了元数据，保存了block与data Node之间的关系；Data Node保存文件数据，保存在磁盘中，维护了block到data node本地文件之间的映射。
  - 适合用途：
    - 存储并管理PB级别数据；
    - 处理非结构化数据；
    - 注重数据处理的吞吐量；
  - 不合适用途：
    - 存储小文件（不建议）；
    - 大量的随机读取（不建议）；
    - 需要对文件修改（不使用）；
- Map Reduce
  - 处理海量数据的并行编程模型，主要用于大规模计算；
  - 流程：split，map，shuffle，reduce
- Pig
  - Pig是SQL-like语言，在map-reduce上构建的一种高级查询语言，把一些运算编译在map和reduce中，并且用户可以定义自己的功能；
- Hive
  - Hadoop中数据仓库工具，可以将结构的数据文件映射到一张数据表，提供完整的SQL查询功能，可以将SQL语句转换为Map Reduce任务执行；
  - 优点：成本低，可以通过类SQL语句快速实现简单Map Reduce统计，不必开发专门的Map reduce应用，十分适合数据仓；
- HBase
  - HBase是Hadoop的数据库，能对大型程序提供实时的读写访问，HBase的目标是存储并处理大规模数据集，存储是松散型数据；
  - 特点：高可靠性，高效性，面向列，可伸缩，成本低（在廉价PC上搭建大规模的结构化存储集群）；
  - 应用场景：
    - 成熟的数据分析主题，查询模式确定且不轻易改变；
    - 传统关系型数据无法承载，告诉插入，大量读取；
    - 适合海量的，也是简单应用（例如key-value）;
- Hadoop核心框架
  - HDFS为海量数据提供存储，Map Reduce为海量数据提供了计算框架
  - HDFS：分布式文件系统
  - Map Reduce：分布式计算框架
  - HBase：实时分布式数据库
3.3 HDFS框架
- Name/Data Node & Client
  - HDFS：有三个重要角色，Name Node(名称节点)，Data Node(数据节点)，Client(客户端)
  - Name Node（名称节点）：Master节点（主节点）可以看做是分布式文件系统中的管理者，负责管理文件系统的命名空间，集群配置信息，存储块复制。将文件系统中的meta-data存在内存中，主要包括文件信息，每一个文件对应的文件块信息和每个文件块的Data Node信息。
  - Data Node（数据节点）：slave节点（从节点）文件存储的基本单元，将Block存在本地文件系统中，保存了Block的meta-data，同时周期地把所存在的Block发送给Name Node。
  - Client：切分文件，访问HDFS，与Name Node交互，获得文件位置信息，与Data Node交互，读取和写入数据。
  - Block：是HDFS中的基本存储单元，HDFS中文件都是切割为block存储的，这些block被复制到多个Data Node中，快大小（通常为64MB）和复制的块数量有Client决定。
- 写入流程
  - 用户向client提出请求，例如写入200M数据；
  - client指定计划，将数据按照64MB为块进行切割，每块保存三份；
  - client将大文件切分为块（block）
  - 对第一个block，client告诉Name Node，复制三份
  - Name Node告诉client三个Data Node地址，并且根据到client的距离排序；
  - client把数据和清单发给第一个Data Node；
  - 第一个Data Node将数据复制给第二个和第三个Data Node;
  - 如果所有数据都写入，向Name Node反馈完成；
  - 依次对剩余的block，重复4~8操作；
  - 所有block都完成后，关闭文件，Name Node将数据持久化到磁盘中；
- 读取流程
  - 用户想client提出请求；
  - client想Name Node请求文件的所有信息；
  - Name Node向client提供文件的块列表，以及存储各个块的数据节点清单（按照距离排列）；
  - client从距离最近的数据节点下载所需的块。
3.4 Map-Reduce框架
- 定义：
  - 本身是一种编程模型，用于大规模数据集的并行计算，主要由两部分组成：Map（映射）和Reduce（化简），其主要思想是从函数式编程中借来的，方便程序员在不会分布式并行编程的情况下，将自己的程序运行在分布式系统中。
- Map Reduce
  - Map：映射，对一些独立元素组成的概念列表中的每一个元素，进行制定操作（对每一个元素独立操作），即并行计算；
  - Reduce：化简，对一个列表的元素进行适当的合并；
- 分布与可靠性
  - Map Reduce把数据集的大规模操作分发到网络中每个节点实现每个节点周期性报告已完成的工作和状态更新；
  - 每个操作使用命名文件的原子操作，确保不会发生并行线程间的冲突，化简操作工作方式很简单，由于简化操作并行能力差，朱借鉴会尽量把化简操作调度在一个节点上；
- 流程：拆分/执行/汇总
  - 向一个MapReduce框架提交一个计算任务时，首先将认为拆分为若干个Map任务，然后分配到不同的节点执行，每一个Map任务处理一部分输入数据，Map任务执行完成后，会生成中间文件，作为Reduce任务的输入数据，Reduce任务的主要目标是将前面若干个Map的输出结果汇总到一起输出。
  - Hadoop将输入数据切分若干分片，并将每一个split交给一个map task处理；
  - Map之后，相当于得到每个task的词频；
  - shuffle将相同的词放在一起并排序，切成分片；
  - 对每个分片进行reduce；
  - 统计reduce task的结果，输出到文件；
  - 两个角色：job tracker和task tracker
    - Job tracker：负责调度和管理，运行在master node中；
    - Task tracker：负责执行任务，运行在slave node，同时必须运行在Data Node中；
- 案例：词频统计
  - Map Reduce伪代码，实现map和reduce两个函数，map函数和reduce函数交给用户实现，这两个函数定义了任务本身；
  - Map函数：接受一个键值对（key-value pair），产生一组中间键值对，map reduce框架会将map函数产生的中间键值对中键相等的值传递给一个reduce函数；
  - Reduce函数：接受一个键以及相关的一组值，将这组值进行合并产生一组规模更小的值（通常只要一个或零个值）
3.5 Map Reduce步骤
基本思想：分而治之，将原始任务分割为若干个子任务，并行执行完成合并在一起，也是并行执行，适用于大量复杂的任务处理场景，大规模数据处理场景；
Map：负责分割，将复杂任务分割为简单任务来处理，前提是简单任务可以并行处理，彼此间没有依赖关系；
Reduce：负责合并，对map的结果进行全局汇总；
客户端提交计算任务后，首先读取输入文件，默认情况下一个block块由一个map task任务处理，完成后经过shuffle，经过分区，排序，规约，分组后，进入reduce，处理后output结果。
Map阶段：
1）经过file input format读取文件，解析为key-value；
2）定义map逻辑，处理（key1, value1）转化为（key2, value2）;
Shuffle阶段：
1. 对（key2, value2）进行分区；
2. 对分区的数据按照key排序；
3. 对分组后的数据进行规约（combine操作）降低数据拷贝；
4. 对排序数据，将相同key的value放入到一个集合作为key2，{value2，…}；
Reduce阶段：
1. 对多个map任务进行合并、排序，自定义reduce逻辑，处理（key1, value1）转化为（key2, value2）；
2. 通过file output format输出处理后的数据，保存到文件；
3.5.1 运行机制详解
首先一个文件被split逻辑划分为多个split文件（切片），通过file input format的record reader收集器，对其结果key分区（默认使用hash分区），然后写入内存缓冲区（buffer），每个map task都有一个内存缓冲器，手机map处理结果，当map task快结束时，合并临时文件形成最终的输出文件，等待reduce task拉取；
详细步骤：
- 读取数据组件input format（默认为text input format），会通过get split方法对输入文件进行逻辑切片得到split，split与block关系默认是一一对应，且每个split启动一个map task；
- 将输入文件分为split之后，有record reader对象（默认为line record reader）进行读取，以’\n’作为分隔符号，读取一行数据，返回<key, value>，key表示每行手字符偏移值，value指一行文本内容；
- 读取split，读取<key, value>，进入用户自己继承的mapper类中，执行用户重写的map函数，record reader读取一行调用一次；
- map逻辑之后，将map的每条结果通过context write进行collect数据收集，在collect中，会先对其进行分区处理，默认使用hash partitioner；分区的作用就是根据key或者value以及reduce数量，决定当前输出数据应该交给那些reduce task处理，默认对key hash之后，在跟reduce数量取模，目的是平均reduce的处理能力；
- 接下来将数据写入内存，叫做缓冲区，作用是批量收集map结果，减少磁盘IO影响，key/value以及partition结果被写入到缓冲区，写入之前key和value都被序列化为字节数组；
- 当内存满时，对key排序，排序是map reduce模型默认行为，若设置了combiner，则将相同key的key/value中value加起来，减少写到磁盘的数据量，combiner会优化map reduce中间结果；
- 合并临时文件，进行merge操作，写入磁盘，并提供一个索引文件；
3.5.2 Reduce Task运行机制
Reduce大致分为copy，sort, reduce三个阶段，reduce task会启动fetch线程copy文件，放入缓冲区中，然后合并磁盘中的文件，生成最终文件；
- copy阶段：简单拉取数据，通过HTTP获取文件；
- merge阶段：内存， 磁盘；
- 合并阶段；把分散数据合并后，并进行排序；
- 调用reduce；
3.5.3 Map Reduce Shuffle过程
将map阶段处理的数据传递给reduce阶段：
Shuffle：洗牌，发牌，核心机制包括数据分区，排序，分组，规约，合并等过程；
- collect阶段：将map task的结果输出到缓冲区，保存key/value；
- spilt阶段：缓冲区溢出，如果配置了combiner，将相同分区号和key进行排序；
- merge阶段：将溢出的临时数据文件进行一次合并操作，确保每个map task只产生一个中间数据文件；
- copy阶段：Reduce task 启动fetcher到map task复制数据，当缓冲区达到阈值，将数据写入磁盘； 
- merge阶段：在reduce task复制数据时，开启线程并合并；
- sort阶段：在合并的同时进行排序，有map task已经进行了局部排序，reduce task 需要保证copy数据整体有效性；shuffle的缓冲区大小会影响到map reduce程序的执行效率，原则上缓冲区越大，磁盘IO的次数越少，速度越快。
